# Audyt wymagań Blackwalla — 2026-10-03

Audyt kodu i dokumentacji wykonany 4 października 2026 r. Zakres: wymagania z `docs/blackwall-koncepcja-i-plan-dema.md`, skrócony dokument dla 5-latka, README, oryginalny brief `docs/golden-sachs.pdf` (4 strony) oraz aktualne `src/`, plugin i testy Blackwalla. Brief na stronach 2–3 wymaga centralnej konfiguracji, hybrydowych kontroli, budżetów API i modeli lokalnych, mitigacji historycznych exploitów, raportowania i automatycznych testów pozytywnych/negatywnych. ## Najwyższe ryzyka

1. **Kod shella działa z uprawnieniami użytkownika systemu.** Jev ocenia komendę, a nie skutki dowolnego kodu i procesów potomnych. Pi wrapper wymusza limit czasu, ale nie jest sandboxem. W README jest to zaznaczone (`blackwall/README.md:103-106`); demo musi używać wyłącznie syntetycznych danych i odizolowanego środowiska.
2. **Punkt egzekwowania istnieje tylko w zarządzanym pluginie.** Klient mający token gatewaya może otrzymać oceniony tool call, ale serwer nie kontroluje wykonania w swoim własnym procesie. Wdrożenie musi zarządzać pluginem, providerem i poświadczeniami oraz ograniczać niezależne ścieżki.
3. **Względne ścieżki zakładają zaufany executor.** Grant wiąże kanoniczne cwd i odrzuca jego zmianę przed claimem. Pi przekazuje runtime cwd; niezależny executor musi wykonać operację z tym samym cwd, albo serwer powinien wymuszać skonfigurowany `workdir` zamiast ufać kontekstowi klienta.
4. **TOCTOU dla plików.** Recheck/hash przed startem wykrywa zmianę zatwierdzonego zasobu przed consume, ale nie atomizuje check z użyciem native Pi tool względem wcześniej otwartego uchwytu. Kontrolowany klient HTTP osobno sprawdza IP podczas lookup socketu (`blackwall/plugin/http-client.ts:24-50`); nie należy przypisywać mu tego samego DNS wyścigu. Plikowa kontrola wystarcza na kontrolowane demo, nie jest granicą bezpieczeństwa dla wrogiego procesu.
5. **Finansowe rozliczenie wszystkich modeli kontrolnych.** Tokenowy budżet auxiliary jest konserwatywnym oszacowaniem, a koszt embedding/guardian może być nieznany. Gdy ustawiono limit USD, system ma fail-closed `COST_UNPRICED`; bez niego należy raportować „nie wyceniono”, nie zero kosztu.
6. **Jakość semantyczna nie jest gwarancją.** Korpus jest mały i autorstwa zespołu; embedding miss, długi kontekst i false positive/negative wymagają pomiaru. Seed `topic_ids` rozwiązuje brak uruchomienia właściwej polityki dla jawnie przypisanej domeny, ale nie rozwiązuje ogólnego odkrywania nieznanych tematów.
7. **Dashboard/audyt to dowód systemowy, nie zewnętrzny.** `tool.started` jest teraz powiązany z claimem, ale sam receipt pochodzi od pluginu. Do silniejszego dowodu potrzebny jest zaufany runner, który raportuje identyfikator procesu i faktyczny wynik.

## Reprodukcje i poprawki w tym audycie

Końcowy przegląd root oraz niezależnych agentów rozszerzył poprawki o:

- **Rekurencyjne wyszukiwanie:** natywne `grep --hidden` mogło przeczytać chronione `.env`, gdy dozwolony był katalog nadrzędny. `plugin/file-tools.ts` teraz filtruje każde źródło przez reguły odczytu, a natywny grep otrzymuje wyłącznie pojedyncze dopuszczone pliki. `find`/`ls` stosują tę samą ochronę nazw. Regresja używa prywatnego tekstu nierozpoznawanego przez DLP, równolegle sprawdzając dostępność wyniku publicznego. Iteracyjne `opendir` ogranicza odkrywanie przed buforowaniem dużego katalogu.
- **Podgląd edycji w Pi:** ustawienie rendererów na `undefined` przywracało domyślny podgląd odczytujący plik przed zgodą. Jawne renderery pokazują wyłącznie nazwę narzędzia i skontrolowany wynik; regresja korzysta z rzeczywistej funkcji Pi `withBuiltInRenderers`.
- **Długi kontekst:** guardian wcześniej otrzymywał uciętą bieżącą wiadomość, co ukrywało naruszenie po długim dozwolonym prefiksie. Teraz analizuje całą bieżącą treść, a ograniczeniu podlega wyłącznie historia; rezerwacja budżetu obejmuje pełny payload.
- **Format wyników i audytu:** inspekcja obejmuje metadane diffów oraz wyjście przed publikacją do RPC/TUI. Regresja wykryła również klucz AWS po JSON-owym `\\n`, którego poprzednia granica słowa nie rozpoznawała. Redakcja, która unieważnia JSON argumentów, kończy się zatrzymaniem odpowiedzi zamiast wykonaniem uszkodzonych argumentów.
- **Rzeczywiste testy dema:** skrypt Python w fixture definiował testy, ale nie wywoływał ich przy uruchomieniu jako program. Dodano wykonywanie asercji i znacznik `TESTS_PASSED`; checker wymaga wyniku rzeczywiście zakończonego wywołania. Brak toolcall nie jest już automatycznie przypisywany samodzielnej odmowie agenta — opis wskazuje dowód działania guardiana albo reguł narzędziowych.
- **Budżet embeddingów i role:** rezerwacja uwzględnia dokładną listę nakładających się fragmentów tekstu; wcześniejszy skrót mógł ją zaniżać. Rola analityka ma jawne `write_roots: []`, aby nie dziedziczyć globalnego prawa zapisu.

Raporty niezależnego przeglądu kodu i kolejnych nagrań znajdują się w `reports/independent-*.md`. Wyniki historycznych reprodukcji niżej opisują konkretny etap prac; aktualny stan całego zestawu opisuje `reports/final-audit.md`.

Dodano `blackwall/test/unit/approval-hardening.test.ts`: zmiana zawartości celu podczas oczekiwania approval, blokada sesji w trakcie pending approval, redakcja przed kontrolą semantyczną i nadzorem, jawne przypisanie topicu mimo braku matcha embeddingowego oraz mismatch/replay jednorazowej zgody wykonawczej. Testy zidentyfikowały dwa realne błędy: approval mogło przywrócić sesję po revoke, a zgoda nie była związana z wersją zawartości celu. Store transition approval jest teraz atomowe względem stanu sesji i TTL, a approval/consume porównują hash zasobu. Grants są dokładnie związane z kanonicznymi argumentami, sesją, requestem, tool, wersją polityki i jednorazowym statusem.

W testach live na `gpt-6-luna` przy niskim reasoning effort przypadki HR `hr-a03`, `hr-a07`, `hr-a08` zweryfikowano ponownie: wszystkie zakończyły się `pass` z `no_identified_violation`, bez `guardian.unavailable`. Pierwotny raport z 3 października pokazywał blokady techniczne dla tych benign przypadków przez niespójne advisory topic arrays (`guardian returned invalid topic decisions`), mimo poprawnego werdyktu. Poprawka filtruje nieznane ID i przy sprzecznych arrays zachowuje `confirmed`, nie osłabiając walidacji policy/verdict/evidence.

Zweryfikowano: `npx vitest run test/unit/approval-hardening.test.ts --pool=forks --maxWorkers=1` — 9/9; wcześniej `npx vitest run test/unit/openai-provider.test.ts test/unit/approval-hardening.test.ts --pool=forks --maxWorkers=1` — 33/33; `npx vitest run test/unit/cost-reservations.test.ts test/unit/files-and-state.test.ts --pool=forks --maxWorkers=1` — 24/24; `npx vitest run test/live/polish.test.ts --pool=forks --maxWorkers=1 -t 'hr-pl-general|hr-pl-policy|hr-pl-negation'` — 3/3; trzy dodatkowe live reprodukcje hr-a03/a07/a08 — 3/3; `npm run typecheck` — poprawny. Nie uruchamiano pełnego płatnego zestawu live/e2e w ramach tej aktualizacji. Pełny zestaw jednostkowy wymaga osobnego uruchomienia po scaleniu równoległych zmian providerów i demo.

## Domknięcie publikacji, 4 października UTC

Ponowny audyt stwierdził, że dawny GET polityki i lokalny YAML nie realizowały wymogu zmiany reguły/progu przez API/UI z efektem w następnej decyzji. Zamiast traktować go jako roadmapę, dodano runtime publication i testy kontraktu. Niezależny przegląd wykrył utratę szyfrowanego reasoning przy wymianie Core oraz ReDoS feedu; oba problemy odtworzono, naprawiono i sprawdzono regresjami. [Przegląd kodu publikacji](../reports/independent-publication-review.md) i [aktualny raport](../reports/final-audit.md) rozdzielają dzisiejszy snapshot od wcześniejszych nagrań.
