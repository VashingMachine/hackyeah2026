## Scope distinction and remaining caveat

The real Pi/OpenAI/Jev segment is the harmless read-and-print interaction completed before publication. The new canary action is submitted afterward by the authenticated session API replay harness, on the same active session; it is not shown as a follow-up command generated and sent by Pi. The evidence therefore proves that the live session decision endpoint applied feed v2 and stopped execution before consume/start. It does not prove that Pi itself attempted the canary. This distinction is explicit in the transcript and demo report and should not be collapsed into a claim that Pi made the denied call.
