BLACKWALL

Hybrid defense: rules for speed, AI for meaning

Rules

Fast, and always the same answer
  • Limits which files an agent may touch
  • Limits where it may send data
  • Protects secrets and personal data
  • Caps token spending
  • Blocks known attacks

AI

Understands what the agent is really trying to do
  • Reviews risky actions before they run
  • Notices when a conversation turns sensitive
  • Judges whether policy is broken, and has to show evidence
  • Strictness: permissive standard strict
A model can’t lift a hard ban. Hard rules always win.
No answer = no approval. If a safety check can’t answer, the action doesn’t run.
Unsure? A human decides. Unclear cases wait for a person to decide.

Strictness and scope

permissive / standard / strict, enforce or observe. Organization and per-user policy combine: allowlists intersect, limits take the minimum.

Budgets

Reserved before every model call. Per session: 400k tokens, 40 tool attempts, 40 model requests, 30 min. Model allowlist. Unknown usage consumes the whole reserve.

Threat feed · 9 signatures

Unsafe pickle / torch.load deserialization, trust_remote_code, curl | sh, reverse shells, leaks to paste sites, prompt injection.

Honest limits, clear path to a pilot

Today

  • No OS sandbox: Jev reviews a command, it can’t contain it
  • Plugin and gateway are the enforcement point
  • Local MVP: SQLite, no SSO, no MCP, no agent-to-agent
  • Runs on OpenAI and Jev; no local-model backend yet

Next

  • Sandboxed runner, credentials outside the agent
  • Central control plane with SSO, PostgreSQL + pgvector
  • MCP and agent-to-agent adapters
  • Local models behind the same gateway; automatic threat-feed ingestion
